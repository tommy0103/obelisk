# Codex cooperative-offset：真实序列 plan-mix 基准

- **日期**：2026-09-18
- **目的**：回答二轮评审的遗留问题——固定 262 B 合成单行后缀天然避开跨边界条件，cooperative 快路径在**真实 append 模式**下的命中率（engage rate）此前未知。本基准重放真实会话的追加序列，统计每个增量 build 实际选择的读计划。
- **输入**：与 2026-09-17 报告相同的本机 top-5 真实 rollout（匿名；仅复制到系统临时目录；未上传、未提交）。
- **方法**：每个输入先索引前一半行建立 checkpoint，然后把剩余行按**真实行序**分批追加，每批触发一次增量 build（parse + persist，内存 SQLite），记录该 build 的 plan。批次粒度（cadence）扫描 1/8/64 行——真实写入事件的批界无法从最终文件还原，cadence 是近似参数。每个（输入 × cadence）最多 200 个 build，重放窗口为 suffix 开头的连续区段。协议代码在 `scripts/bench-codex-cooperative-offset.mjs` 的 `--replay` 模式。
- **环境声明**：warm-cache、内存 SQLite、单机；只计时 parse+persist。

## 结论

1. **engage rate：80.2–99.0%，中位 93.5%**。真实 append 模式下 cooperative 快路径占绝对主导；固定合成后缀的 "5/5 全选" 不再是唯一证据。
2. **所有回退均为 snapshot，且全部由真实重复对骑界触发**（event_msg/response_item 两种表示落在 checkpoint 两侧）——这是跨边界 Bloom 检查的正确保守行为，与收敛测试钉死的 K=64 场景同源。未出现 malformed、verified 或 noop。
3. **加权平均 build 成本全面低于 main 的固定全量重扫**：改善幅度 1.4×–68×（15 组中位 11.1×）。
4. **诚实负面**：单次回退代价（中位 227–834 ms）高于 main 的全量重扫（188–466 ms），与 09-17 报告的发现一致（snapshot 路径 3 遍全量读＋delete/全量重插）。最差组合（输入 4、cadence 8/64、约 20% 回退率）净收益收窄至 ~1.4–1.6×。**降低 snapshot 回退成本**（例如 snapshot 时跳过 fingerprint、合并扫描遍次）仍是已登记的最有价值的后续优化项。
5. cadence 敏感性非单调：输入 4 在粗 cadence 下回退率反而升高（11.5%→19.8%），因为单批跨越更多重复对的间距分布；其余输入随 cadence 变粗持平或略降。真实收益依赖会话内重复对的间距结构，无法从单一 cadence 外推。

## 局限

- 单机、warm-cache、内存 SQLite；不含 discovery/watcher/FTS finalize。
- 每输入只重放 suffix 开头的一个连续窗口（≤200 builds），非整段会话。
- cadence（1/8/64 行/批）是近似：真实写入事件的批界不可知。结论应理解为"跨 cadence 的量级与下界"，而非精确的生产分布。
